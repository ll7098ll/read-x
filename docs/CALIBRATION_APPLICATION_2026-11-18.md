# 승인된 파일럿 보정의 실제 진단·배치·자료 선정 적용

<!-- readx-document-context -->
> 작성 당시의 설계·조사·구현 기록입니다. 현재 기능과 운영 상태는 최신 현황을 우선합니다. [문서 목차](README.md) · [최신 현황](PROJECT_STATUS.md)


2026년 11월 18일. 교사가 승인한 보정 난도를 반별로 활성화해 새 레벨 테스트의 문항 순서·추가 분기·코스 추천과 새 코스의 성취 확인 자료 선정에 반영한다. 표본이나 검증 조건을 충족하지 못한 문항은 기존 기준을 사용한다.

## 수업에서 사용하는 순서

1. 기존 **교사 검수·수업 파일럿**에서 문항 검수, 학생 관찰, 문항 난도 보정 승인을 마친다.
2. 교사 수업 화면 `#/teacher/classes`에서 **보정 난도 적용·전후 비교 열기**를 누른다.
3. 담당 반, 비교할 학생, 자료 학년을 고르고 **적용 전후 미리보기**를 연다. 이 미리보기는 현재 교사 자신의 승인 자료를 사용한 제안이다. 학생의 응답·배치·계획을 변경하지 않는다.
4. 유효한 보정 수와 기존 기준으로 유지되는 사유, 공통 진단 순서, 동일 응답에 대한 코스 추천, 성취 확인 후보 순서를 비교한다. 이전 문항 버전이거나 선택형 응답이 아직 없으면 코스 추천의 가상 점수를 만들지 않는다.
5. **이 반의 새 진단·코스에 내 승인 보정 사용**을 선택하고 운영 의견과 함께 설정을 저장한다. 해당 반에 어느 교사의 기준을 쓰는지 기록한다. 다른 교사가 정한 기준은 기존 담당자 또는 운영자만 바꿀 수 있다.
6. 이후 학생이 시작하는 진단과 교사가 새로 승인하는 4주 계획에 적용된다. 교사는 진단 응답 검토와 코스 미리보기에서 실제 적용 전후 기록을 확인하고 최종 배치·수업을 승인한다.

적용을 끄면 이후 새 응시·새 계획은 기존 기준을 사용한다. 이미 진행 중인 진단과 승인된 코스의 문항·기준·비교 기록은 바꾸지 않는다. 학생에게 교사 전용 보정 원자료나 정답표는 전달하지 않는다.

## 적용에 필요한 조건과 기존 기준 유지

반에서 지정한 교사가 현재도 해당 반의 수업 권한을 가지고 있어야 한다. 같은 학년·문항 내용 버전에서 다음 조건을 모두 확인한다.

| 조건 | 적용하지 않는 경우 |
| --- | --- |
| 교사 문항 검수와 난도 보정 승인 | 미승인, 수정 필요·재검수 대상 |
| 현재도 첫 독립 수행 20명 이상 | 저장된 승인이 20명이어도 현재 유효 표본이 19명 이하이면 유지 |
| 승인 시점과 현재 관찰 자료의 일치 | 도움·노출·판정·시간·조회 권한 등의 변경으로 원자료가 달라졌으면 유지 |
| 같은 문항 내용 식별값과 보정 방식 | 본문·선지·정답·근거·해설 등의 버전이 다르거나 지원하지 않는 방식이면 유지 |
| 실제 통계와 승인된 표본 수·정답률의 일치 | 저장 정보가 현재 분석과 다르면 유지 |

도움·기노출·재응시·미검토·관찰 불가의 제외 규칙은 파일럿 분석과 같다. 현재 담당하지 않거나 일반 처리가 정지된 학생은 표본에 넣지 않는다. 다른 교사의 원자료를 자동으로 합치지 않는다. 미리보기에서 표본 부족·자료 변경 등 주요 유지 사유를 문항별로 펼쳐 볼 수 있다.

표본이 부족한 문항에는 보정값을 붙이지 않는다. 해당 문항의 기존 난도와 정답 판정, 선정용 보정값 0을 유지한다. 자격을 충족한 다른 문항은 계속 적용할 수 있다. 유효 보정이 전혀 없으면 기존 문항 순서·분기·추천·후보 순서를 그대로 사용한다.

## 레벨 테스트와 코스 추천에 어떻게 반영하는가

학년별 문항 수·기능 구성·정답표·설명 과제는 유지한다. 공통 진단과 추가 진단 각각에서 같은 본문에 속한 선택형 문항의 순서를 조정하고, 공통 응답에 따른 지원형/확장형 분기에 보정 점수를 사용한다. 설명 과제는 마지막에 유지한다. 공통 문항은 추가 분기로 넘어가도 답·선지·순서가 유지된다.

원래 정답 수와 정답률은 바꾸지 않는다. **선정용 보정 점수**를 별도로 계산한다.

```text
문항 보정값 = clamp(0.70 - 승인 정답률, -0.15, +0.15)
기능별 선정용 점수 = clamp(원래 정답률 + 문항 보정값의 평균, 0, 1)
미적용 문항의 보정값 = 0
```

예를 들어 두 어휘 문항 중 하나를 맞힌 원래 정답률은 50%로 유지된다. 두 문항이 모두 유효하게 승인된 어려운 문항이고 각각 +0.15를 적용하면 선정용 점수는 65%이다. 공통 단계의 기존 60% 분기 기준에 이 점수를 넣으면 지원형 대신 확장형을 선택할 수 있다. 정답으로 바꿔 채점한 것은 아니다.

추가 진단 이후에는 기능별 기존 70% 추천 기준과 어휘 60% 글 수준 기준에 선정용 점수를 넣어 코스·수준을 추천한다. 최종 배치는 교사가 원응답·구두 설명·읽기 관찰을 함께 확인해 결정한다. 미적용일 때에는 기존 계산을 그대로 사용한다. 모든 문항을 틀린 결과가 이 보정만으로 분기 기준을 통과할 수 없도록 보정 폭을 제한했다.

70% 기준점과 ±15%p 한도는 이 구현의 운영 휴리스틱이다. 문항반응이론에 의한 능력 추정이나 검증된 점수 등화·전국 규준이 아니다. 실제 학급의 배치 결과를 관찰해 정책 버전별로 검토해야 한다. 교사 화면에서는 원점수·원래 비율·선정용 점수·적용 문항 수를 구분한다.

## 성취 확인 자료 선정

새 코스 승인 시 현재 유효한 보정을 문항별로 저장한다. 도움글은 입문, 기준글은 기본, 도전글은 도전을 목표 난도로 삼는다.

- 승인 보정으로 목표 난도에 더 가까워진 문항을 주 후보 안에서 우선한다.
- 목표에서 더 멀어진 문항은 뒤로 조정한다.
- 미보정 문항끼리는 기존 상대 순서를 유지한다. 보정 전후 난도가 같은 경우에는 기존 순서를 바꾸지 않는다.
- 독립 확인·새 상황 적용·유지 확인의 용도는 섞지 않는다. 대체 자료는 주 후보가 없을 때 사용하도록 뒤에 남긴다.
- 이미 본 자료는 기존 문항 계열 단위 노출 규칙으로 제외한다. 선정 가능한 새 자료가 없으면 기존처럼 새 자료를 요청한다.

교사는 승인 전 후보의 기존 순서와 적용 순서를 볼 수 있다. 학생이 실제 확인 활동을 열면 미노출 후보 중 기존 방식으로 골랐을 자료와 실제 고른 자료를 함께 기록한다. 원래 정답·근거·설명 준거, 최근 5개 중 4개 성공, 여러 날짜, 전이·유지 확인과 교사 승인 조건은 바꾸지 않는다.

## 적용 전후 비교의 해석과 기록 고정

진단 비교는 두 부분으로 나뉜다.

1. **공통 단계의 실제 분기 비교**: 동일한 공통 응답으로 기존 지원형/확장형 선택과 실제 선택을 기록한다.
2. **실제 응시한 동일 문항의 추천 비교**: 최종 실제 응답에 기존 계산과 보정 계산을 각각 적용한다. 다른 분기의 문항을 풀었다면 어떻게 답했을지는 예측하거나 채워 넣지 않는다.

진단 시작 시 보정 자료·운영 정책·공통 및 두 추가 분기 문항을 고정한다. 진행 중에 표본이 줄거나 새로운 승인이 생겨도 해당 응시의 기준을 중간에 바꾸지 않는다. 이후 새 응시는 최신 자격을 다시 확인한다. 이전 버전 진단은 새 문항의 응답으로 재활용하지 않는다.

코스 미리보기에는 보정 기준과 후보 순서를 포함한 내용 식별값이 붙는다. 승인 전에 관찰 자료나 반 설정이 바뀌면 오래된 미리보기로 승인할 수 없고 다시 검토해야 한다. 승인된 계획은 후보 순서·보정 출처·정책을 고정하며, 이후 설정 중지나 표본 변경으로 소급 변경하지 않는다. 단계 이동으로 새 계획을 승인할 때는 최신 기준을 다시 확인한다.

운영 정책 버전은 `approved-calibration-application-1`이다. 교사 기록에는 반의 적용 설정과 이력, 응시별 보정 출처·문항 버전·유지 사유·분기 및 추천 비교, 코스별 후보 순서, 실제 확인 자료의 선정 비교가 저장된다. 학생 응답에서는 미래 분기 정답표·표본 통계·교사 전용 비교 자료를 제외한다.

## 검증과 재현

`webapp`에서 `node --test server/calibration-application.test.mjs`와 `npm run build`를 실행한다. 무적용 시 동일 결과, 유효 표본 적용, 19명 복귀, 추천 변화, 실제 확인 자료 변경, 진행 중·승인된 기록 보존, 오래된 미리보기 차단, 다른 반·역할·설정 버전 제한, 이전 문항 버전 재사용 방지와 대체 자료 보존을 검사한다.

브라우저 검증은 `webapp/scripts/preview-calibration-ui.mjs`의 임시 메모리 DB에서만 실행한다. 프로젝트 루트에서 `python scripts/verify_calibration_application_browser.py`를 실행하면 가상 학생 20명의 실제 파일럿 요청으로 7개 승인 보정을 만들고, 별도 학생에게 새 진단·코스·확인 활동을 배정해 전후 차이와 19명 복귀를 확인한다. 실제 학생이나 운영 DB에는 쓰지 않는다. 결과는 `output/calibration-application-2026-11-18`에 저장한다.
