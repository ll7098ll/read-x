# 다섯 번째 개발 묶음: 보호자 확인·동의와 이용 제어

> 작성 당시의 설계·조사·구현 기록입니다. 현재 기능과 운영 상태는 최신 현황을 우선합니다. [문서 목차](README.md) · [최신 현황](PROJECT_STATUS.md)


2026년 11월 14일. 직접 운영 학원, 교사 등록 → 법정대리인 확인 → 보호자 동의·연결이라는 사용자의 운영 방식을 구현했다. 사업자·개인정보 담당자·실제 확인 절차와 법률 검토·국내 업체 계약은 미확정이다. 이 묶음은 동의 절차를 지원하는 기능 구현이며 적법성 인증이나 실제 개인정보 운영 승인 결과가 아니다.

## 동작

1. 기본 서버 모드는 `enforced`다. 운영자가 사업자명·담당 연락처·필수 목적과 항목·보유기간·거부 권리와 영향·어린이 안내·보호자 확인과 철회 방법·사전 등록 근거·검토 문서 참조를 작성해 안내문 버전을 게시한다. 미리 작성된 운영 방침이나 승인된 법률 문구는 넣지 않았다.
2. 교사는 게시된 사전 등록 기준에 맞는 별도 문서 관리 번호를 입력해 최소 계정을 등록한다. 등록 사실이 동의로 처리되지 않는다. 학생 로그인과 읽기·시험 배정은 차단된다. 동의 전에 수집할 수 있는 최소 정보와 근거는 실제 처리에 맞춰 별도로 검토해야 한다.
3. 운영자는 학원의 검토된 대면 또는 서면 절차로 본인·법정대리인 관계를 확인한 뒤, 별도 보관 문서 참조·확인 사유·시점·확인자를 기록한다. 원본 신분증·주민등록번호·가족관계 문서 파일을 받는 업로드 기능은 추가하지 않았다. 이 기록 자체가 외부 본인인증이나 법률 검토를 수행하지 않는다.
4. 보호자는 로그인 후 초기 비밀번호를 변경하고 안내문을 확인한다. 필수 수집 동의는 체크되지 않은 상태로 시작하며 선택 항목마다 동의/비동의를 직접 선택한다. 선택 거부는 필수 학습을 막지 않는다. 선택 내용을 이용하는 실제 문자·결제·외부 AI 연동은 아직 없다.
5. 동의 사건은 보호자·학생·확인 기록·안내문 ID와 해시·선택별 결정·시각·요청 ID를 포함해 추가 저장한다. 게시된 안내문과 이전 동의 사건을 덮어쓰는 API는 없다. 보호자는 당시 안내문과 선택 이력을 조회할 수 있다.
6. 동의가 성립해야 학생 로그인이 가능해지고 보호자에게 자녀 학습정보 연결이 생긴다. 보호자는 동의 전에도 자기 계정과 확인·동의 화면을 이용할 수 있다. 교사는 담당 반, 운영자는 자기 기관 범위만 조회한다.
7. 필수 동의 철회·보호자 확인 해제·확인 유효기간 만료·안내문 새 버전 게시 시 서버가 학생 이용과 보호자의 해당 학습정보 접근을 다시 판단한다. 철회·확인 해제·새 안내문 게시 시 학생 세션도 해제한다. 이전 동의 요청을 재전송해도 이용이 재활성화되지 않는다.
8. 기관별 동의·안내문·확인 이력을 분리한다. 기존 계정의 보호자 링크는 확인 대기 후보로만 이관하고 동의를 생성하지 않는다. 계정 활성 체크와 기존 연결 수정 API로 동의를 우회할 수 없다. 퇴원은 기존 확인 이력을 해제한다.

로그인 전 안내문 조회, 운영자의 안내문 게시·확인·해제, 보호자의 동의·철회·당시 안내문 조회를 화면에 연결했다. 학습 배정 목록에서는 동의가 완료된 이용 가능 학생을 선택한다.

## 검증

`server/privacy.test.mjs`는 기본 강제 모드에서 실제 HTTP 서버로 다음 8개 시나리오를 검증한다.

- 안내문과 등록 근거 없이 등록 차단, 확인·초기 비밀번호 변경 전 동의 차단, 필수/선택 결정·해시 검증.
- 선택 거부 상태의 이용 허용, 철회 후 기존 학생 세션·리포트·출력 접근 차단, 요청 재전송의 중복 방지와 재활성화 방지.
- 안내문 변경 후 재동의, 기존 안내문 이력 보존, 읽기 배정과 시험 배정 모두 차단.
- 확인 해제·재확인·만료·다른 보호자로 변경 시 기존 동의 재사용 방지와 기존 API 우회 차단.
- 일반 교사·다른 보호자의 위조 요청과 다른 반 열람 차단.
- 서버 재시작 후 사건·안내문 보존 및 운영 모드의 가상 검증 DB 거부.
- 기존 보호자 링크를 동의로 추정하지 않는 이관.
- 같은 DB의 다른 기관 운영자가 동의·확인 기록을 읽거나 수정하지 못하는지 확인.

기존 학습·평가·운영 테스트는 명시적인 `privacyMode:'synthetic'` 가상 자료 모드에서 기존 도메인을 검증한다. 신규 동의 검사는 기본 `enforced` 모드를 사용한다. 가상 모드에서 실제 동의 API는 작동하지 않으며 `READX_RUNTIME=production`은 가상 모드 옵션과 가상 기관이 들어 있는 DB를 거부한다. 웹 API로 모드를 바꾸는 경로는 없다.

최종 전체 빌드, UI·학습 도메인 79개와 서버·운영 32개를 합한 111개 검사, 운영 시험 자료의 번들 비노출·외부 자동 리소스 검사까지 통과했다. 결과는 `output/consent-build-2026-11-14.log`에 기록했다. 학생 등록 후 별도 보호자 계정 추가도 지원하며, 계정 추가만으로 자녀가 연결되지 않는다. 사용자에 의해 중단된 컴퓨터 제어는 재개하지 않았으며, 브라우저·모바일의 전체 조작과 접근성 검증은 남아 있다.

## 운영 전 남은 사항

- 안내문은 동의 수집을 위한 운영 입력 기능이다. 실제 개인정보 처리방침 전체 항목·이용약관·위탁/국외이전 고지 등은 실제 처리와 업체 확정 후 법률 검토가 필요하다. 텍스트와 검토 참조의 존재를 검사하는 코드가 그 내용의 적법성을 판단하지 않는다.
- 본인·법정대리인 확인의 구체적 증빙·진위 확인·권한 분쟁·계정 정보 전달 절차는 운영자가 확정해야 한다. 현재는 학생마다 이용 승인에 쓰는 활성 확인자를 한 명으로 제한한다. 복수 법정대리인과 양육권 분쟁은 별도 절차가 필요하다.
- 원장은 초기 보호자 비밀번호를 알 수 있다. 비밀번호 변경만으로 본인 확인이 성립하지 않는다. 검토된 오프라인 확인·안전한 계정 전달·보호자 본인 접근이 전제이며, 외부 본인인증 도입 여부도 검토해야 한다.
- 철회는 새 요청과 학습정보 접근을 차단한다. 기존 저장 데이터의 파기·법정 보존·백업 만료와 복원 후 재파기·다운로드본 관리, 열람/정정/삭제 등 권리 행사 접수는 별도 개발과 검증이 남아 있다. 이미 전달된 출력물을 원격으로 회수하지는 못한다.
- 사건·안내문은 현재 계정 원장의 SQLite JSON에 저장된다. API의 수정 금지와 별개로 DB 관리자에 대한 변조 방지·접근기록 보호·암호화·보존기간 통제는 아직 완료되지 않았다. 읽기 초안의 공유 기기 잔류 문제와 관리자 추가 인증도 남아 있다.
- 23개 운영 준비 통제의 검토 완료 표시는 변경하지 않았다. 운영 사업자·서버·계약·실제 동의 문서와 법률 검토·현장/침투/복구 시험이 갖춰지기 전까지 전체 운영 전환 목표는 진행 중이다.

동의를 법적 근거로 처리하는 만 14세 미만 아동에 대해 법정대리인 동의와 확인을 요구하는 조문을 참고했다. 실제 사전 등록·교습 계약·기록 보관 등 각 처리의 근거는 구분해서 검토해야 한다. [개인정보 보호법 제22조의2](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335069), [개인정보 포털의 법정대리인 역할 안내](https://www.privacy.go.kr/front/contents/cntntsView.do?contsNo=75).
