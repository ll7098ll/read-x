## 학습을 설계하는 두 축

사고 활동과 도움 수준을 서로 다른 축으로 관리한다. 단서 찾기·관계 연결·조건 점검·설명하기는 수행할 사고 활동이며, 시범·함께 연습·도움 줄이기·혼자 수행은 그 활동을 수행하는 지원 조건이다. 단서 찾기를 했다고 초급, 설명을 썼다고 고급으로 판정하지 않는다.

| 도움 수준 | 화면의 지원 | 학생에게 남기는 활동 |
| --- | --- | --- |
| 시범 | 교사의 표시와 생각을 한 단계씩 제시 | 다음에 볼 단서를 예상하고 시범 이유 확인 |
| 함께 연습 | 목표 도구와 짧은 이유 틀 제공 | 구절 선택·관계 설명·원문 점검 |
| 도움 줄이기 | 정답 구절 미표시, 필요할 때 질문 열기 | 스스로 단서 찾고 도움 요청 여부 결정 |
| 혼자 수행 | 목표·본문·필수 도구 제공 | 표시 필요성을 판단하고 자기 설명 제출 |

준비된 학생은 시작 과제의 수행이나 교사 설정에 따라 일부 시범을 건너뛴다. 도움이 필요한 학생은 같은 목표에서 이전 지원 단계로 돌아갈 수 있다. 모든 학생에게 모든 단계를 같은 분량으로 반복시키지 않는다.

## 학생의 읽기 공간

넓은 화면은 본문과 생각 패널을 나란히 배치한다. 본문 위에는 목표·현재 단계·필요한 표시 도구를 두고, 패널에는 한 번에 한 가지 생각 질문과 다음 행동을 보여 준다. 선택한 구절을 눌러 본문 위치와 설명을 함께 확인한다.

태블릿과 작은 화면에서는 본문 위 선택 도구와 하단 생각 패널을 사용한다. 본문/활동을 전환해도 현재 질문·선택 구절·스크롤 위치를 유지한다. 패널이 선택한 구절이나 다음 버튼을 가리지 않아야 한다.

교사 시범, 학생 표시, 교사 검토는 색만으로 구분하지 않는다. 각 표시와 메모에 ‘선생님 시범’, ‘내 생각’, ‘선생님 의견’을 붙이고 서로 다른 모양·테두리를 함께 사용한다. 표시를 숨겨도 원래 기록은 유지한다.

| 표시 출처 | 편집 권한과 화면 행동 |
| --- | --- |
| 교사 시범 | 검수한 콘텐츠 버전에 귀속, 학생은 보기·숨기기·다시 보기 |
| 학생 표시 | 학생이 편집·삭제·복원, 제출 후에는 새 수정본 생성 |
| 교사 검토 | 제출본의 구절·표시·설명에 연결, 학생 원본을 덮어쓰지 않음 |

## 목표에 필요한 표시 도구

한 수업에서는 목표에 필요한 도구 2~3종만 먼저 보여 준다. 다섯 도구를 상시 전부 노출하지 않으며, 추가 도구는 학년과 수업 목표에 맞춰 펼친다. 기호의 의미는 범례·도구 이름·사고 질문·검토 기준에서 일치해야 한다.

| 도구 | 학생이 수행할 생각 | 사용할 수업 예 |
| --- | --- | --- |
| 대상 □ | 지금 무엇의 뜻이나 상태를 살피는가 | 정의, 지시 대상, 핵심 대상 |
| 근거 밑줄 | 내 설명을 뒷받침하는 말은 무엇인가 | 사실 확인, 추론, 주장 검토 |
| 관계 → | 두 구절이 어떤 관계인가 | 정의와 예, 원인과 결과, 비교 |
| 조건 괄호 | 언제 성립하며 어디까지 적용되는가 | 조건, 범위, 예외와 반례 |
| 질문 ? | 어디가 아직 불분명하며 무엇을 다시 볼까 | 이해 점검, 재독, 질문 해결 |

처음부터 모든 문장에 표시하도록 요구하지 않는다. 표시 자체가 학습 목표인 일부 활동에서만 의미 있는 최소 표시를 요구한다. 예를 들어 ‘조건 두 가지를 구별해 설명하기’에서는 필요한 구절과 구별 이유를 확인하며, 표시 개수만 채우는 완료 조건은 만들지 않는다.

## 구절 선택과 관계 연결

1. 학생이 본문에서 구절 범위를 고르면 가까운 위치에 필요한 도구만 열린다.
2. 선택 도구에 원문 인용과 시작·끝 조절을 제공하고, 선택이 불편하면 문장→단어 칩 순서로 범위를 좁힌다.
3. 관계는 출발 구절을 선택한 뒤 도착 구절을 고른다. 두 구절은 같은 문장 안에 있어도 된다.
4. 관계의 종류와 이유를 남긴다. 관계 종류는 수업 목표에 맞춰 제시하며 자유 설명을 허용한다.
5. 저장한 표시를 누르면 이유·편집·삭제를 볼 수 있다. 직전 작업 실행 취소와 삭제 복원을 제공한다.

구절 앵커는 문장 ID와 문자열뿐 아니라 원문 버전, 시작·끝 위치, 실제 인용문, 앞뒤 문맥을 보존한다. 같은 말이 반복되어도 선택한 위치를 구분한다. 현재 첫 문자열 일치에 표시하는 방식은 새 앵커 형식으로 대체하고 기존 기록의 모호한 위치는 검토 대상으로 표시한다.

키보드는 문장 이동→범위 시작→범위 확장→도구 선택 순서로 조작하고 현재 선택을 읽어 준다. 터치는 길게 누르기와 선택 손잡이를 지원하되 문장·단어 칩 대안도 제공한다. 연결선이 겹치거나 작은 화면에서 복잡해지면 ‘출발 구절 → 도착 구절’ 카드로 동일 정보를 제공한다.

원문이 바뀌면 이전 표시를 새 글에 조용히 이동시키지 않는다. 제출본은 원래 원문 버전으로 재현하고, 새 버전의 재사용은 앵커 재검토를 거친다. 정확히 복원할 수 없는 구절은 ‘연결 위치 확인 필요’ 상태로 남긴다.

## 표시한 이유를 자기 설명으로 이어 가기

기본 흐름은 **구절 선택 → 이유 말하기 또는 쓰기 → 내 설명으로 가져오기 → 원문과 비교해 수정**이다. 표시 메모, 답, 이유를 같은 내용으로 세 번 쓰게 하지 않는다. 학생이 남긴 구절·관계·이유를 설명 패널로 가져와 연결 문장으로 다듬게 한다.

| 학생 행동 | 화면 반응 | 보존할 내용 |
| --- | --- | --- |
| 구절을 고름 | 선택한 원문 인용을 생각 패널에 표시 | 선택 범위와 도구 |
| 이유를 남김 | ‘내 설명에 쓰기’ 제공 | 학생의 원래 표현 |
| 설명에 가져옴 | 인용과 이유를 편집 가능한 문장으로 배치 | 출처 표시 ID와 수정본 |
| 다른 근거를 발견 | 처음 생각을 유지하며 고쳐 쓰기 | 수정 전후와 선택적 수정 이유 |
| 제출 | 제출 시점 본문·표시·설명 고정 | 제출본과 도움·노출 조건 |

저학년은 짧은 문장 틀과 교사 대필을 지원하고, 대필 여부를 기록한다. 소리 내 말한 뒤 짧게 쓰는 활동은 녹음 없이 가능하다. 녹음이 추가되더라도 녹음 길이와 발화량을 읽기 능력 점수로 사용하지 않는다.

## 사고 시범과 자기점검

사고 시범은 단순 정답 해설이 아니라 ‘어떤 말을 먼저 봤는가→왜 중요하다고 생각했는가→다른 단서와 어떻게 연결했는가→어디를 다시 확인했는가’를 보여 준다. 틀린 추측을 점검하고 고치는 장면도 필요한 목표에 포함한다.

본문의 구절 강조와 생각 말풍선은 단계에 맞춰 함께 바뀐다. 이전 단계의 표시를 유지하거나 잠시 숨겨 비교할 수 있고, 어느 단계든 다시 볼 수 있다. 교사 표시를 다시 열어 본 경우에는 노출 이력을 남기되 학생의 도움 요청을 실패로 표현하지 않는다.

자기점검은 “원문에 없는 말을 보탰나”, “조건을 바꾸어 읽었나”, “이 예 하나를 모든 경우로 넓혔나”처럼 목표에 맞는 질문 1~2개로 구성한다. 독립 수행에서는 자동으로 답을 드러내는 질문을 먼저 펼치지 않는다.

## 조건을 구별하는 수업 시안

다음은 상호작용 설명을 위한 **검수 전 시안**이다. 실제 온실 제어에 관한 일반 지식이 아니라 아래 짧은 글의 규칙을 읽는 과제이며, 출시 전에 학년·문장 난도·오개념 가능성을 검수한다.

> 온실의 온도가 28도 이상이면 창문을 연다. 온도가 24도 이하이면 창문을 닫는다. 24도보다 높고 28도보다 낮으면 창문은 바로 전 상태를 유지한다.

질문: “온도가 28도여서 창문이 열렸다. 그 뒤 26도가 되었다면 창문은 어떤 상태일까?”

| 단계 | 본문의 표시와 조작 | 텍스트 사고구술 시안 |
| --- | --- | --- |
| 질문 확인 | ‘28도여서 창문이 열렸다’와 ‘그 뒤 26도’ 구별 | “지금 온도만 보면 될까? 직전에 열린 상태였다는 말도 있네.” |
| 조건 구분 | ‘28도 이상’, ‘24도 이하’를 조건으로 표시 | “26도는 새로 여는 조건에도, 닫는 조건에도 해당하지 않아.” |
| 필요한 근거 선택 | ‘24도보다 높고 28도보다 낮으면’, ‘바로 전 상태를 유지’ 선택 | “26도는 이 사이에 있으니까 바로 전 상태를 확인해야겠어.” |
| 관계 연결 | ‘바로 전 상태를 유지’와 질문의 ‘창문이 열렸다’를 연결 | “직전에는 열려 있었어. 그 상태를 유지하니까 지금도 열려 있어.” |
| 자기점검 | 처음 설명과 조건을 함께 확인 | “28도보다 낮다고 무조건 닫는다고 읽으면 안 되겠구나. 닫는 조건은 24도 이하야.” |

질문의 상황 문장도 선택 가능한 앵커 영역으로 제공하여 본문 근거와 연결한다. 함께 연습에서는 ‘조건·근거·관계’ 세 도구를 보여 준다. 다음 연습은 수치만 바꾸는 데서 끝내지 않고, 닫힌 상태에서 중간 구간으로 이동하는 상황과 처음 보는 다른 소재의 유지 규칙을 준비한다.

## 도움과 미노출 글의 수행 구분

‘혼자 수행’은 화면의 단계 이름만으로 판정하지 않는다. 제출 전의 시범 보기·도움 질문·예시 답안 보기·이전 제출과 피드백 노출을 함께 기록한다. 기기나 글 수준을 바꿔도 같은 지문 계열을 이미 읽었다면 미노출 글로 다시 계산하지 않는다.

같은 본문에서 새로운 보기에 적용한 기록과 처음 보는 글에서 같은 전략을 사용한 기록을 구분한다. 두 기록 모두 학습 증거로 쓰되 서로 다른 수행 조건을 명시한다. 도움을 열어도 진행을 막지 않고 ‘도움과 함께 수행’으로 남긴다.

## 데이터와 저장 계약

| 기록 | 필요한 필드와 기준 |
| --- | --- |
| 원문과 수업 | passageId, passageVersion, contentFamilyId, lessonVersion, goalId, 학년·수준 |
| 구절 앵커 | 영역 종류, 문단·문장 ID, start/end, exactQuote, prefix/suffix |
| 표시 | annotationId, 도구 종류, 출발 앵커, 선택적 도착 앵커, 관계 종류·이유 |
| 작성 출처 | learnerId, assignmentId, sessionId, authorRole, authorId, 대필 여부 |
| 수정 이력 | revisionId, 이전 revisionId, 생성·수정 시각, 변경 종류, 선택적 수정 이유 |
| 도움과 노출 | 시범 단계·질문·해설 노출 시각, 지문 계열 노출, 제출 전후 순서 |
| 제출과 검토 | submissionId, 표시·설명 스냅샷, reviewId, 검토 주체·기준·구절 피드백 |
| 저장 상태 | 기기 임시 저장, 서버 저장 완료, 동기화 대기, 실패·재시도 상태 |

학생 화면은 서버 저장이 확인되기 전에 ‘제출 완료’로 표시하지 않는다. 네트워크가 끊기면 입력과 표시를 복구하고 재시도하며, 중복 전송은 같은 제출로 처리한다. 교사와 학생이 동시에 수정하더라도 제출본과 검토본을 덮어쓰지 않는다.

## 교사의 근거 검토와 다음 지도

검토 화면은 본문·학생 표시·자기 설명·도움·수정 전후를 나란히 보여 준다. 교사는 선택 구절의 적절성, 관계 설명의 타당성, 조건·예외 반영, 설명의 원문 충실성을 목표에 맞춰 확인한다. 자동 확인된 선택 결과와 교사가 확인한 설명 수행은 구분한다.

교사는 표시나 설명의 특정 부분에 “두 조건 중 어느 것이 여기에 해당하니?” 같은 다음 질문을 남기고 재시도 또는 다음 글을 배정한다. 학생은 해당 구절로 돌아와 피드백을 확인하고 새 수정본을 제출한다. 부모에게는 교사가 확인한 실제 사례와 다음 지도 방향을 보여 준다.

표시 횟수·밑줄 길이·메모 글자 수를 능력 점수로 사용하지 않는다. 도움 없이 관련 구절을 찾았는지, 연결을 설명했는지, 조건을 반영했는지, 새 글에서도 같은 방법을 사용했는지를 제출 사례와 함께 제시한다. 표본이 부족하면 안정된 능력으로 단정하지 않는다.

## 콘텐츠 제작과 검수

수업 패키지는 원문과 목표, 시범 대본과 앵커, 학생 활동, 도움 질문, 자기점검, 독립 확인 지문, 검토 기준을 함께 갖춘다. 표시 위치만 맞는 예와 이유까지 타당한 예를 구분하여 검토자가 동일한 기준으로 판단할 수 있게 한다.

콘텐츠 편집자는 시범 표시·학생 초기 화면·도움 노출 후 화면·교사 검토 화면을 미리 본다. 모든 앵커가 실제 원문에 존재하는지, 조건을 누락하지 않았는지, 독립 확인에 시범의 정답 표시가 남지 않는지 확인한 뒤 버전을 발행한다.

## 구현 순서와 완료 조건

| 순서 | 구현 범위 | 검증 가능한 완료 조건 |
| --- | --- | --- |
| 1 | 공통 읽기 공간과 표시 출처 | 두 플레이어에서 같은 도구·출처 표시·본문 이동을 사용하며 학생 원본과 교사 의견이 구별됨 |
| 2 | 범위 앵커와 표시 편집 | 반복 구절·같은 문장 관계·겹친 표시·원문 변경을 처리하고 터치·키보드로 동일 작업을 완료함 |
| 3 | 사고 시범과 설명 재사용 | 시범 단계와 본문이 동기화되고 선택한 이유를 설명으로 가져와 중복 작성 없이 수정·제출함 |
| 4 | 공식 저장과 교사 검토 | 학생의 제출본이 교사에게 같은 버전으로 보이고 구절 피드백·재제출·복구가 이어짐 |
| 5 | 전략별 콘텐츠와 새 글 확인 | 각 출시 목표에 검수한 시범·연습·도움·미노출 확인·검토 기준이 모두 존재함 |

기능 검증은 선택 위치 정확성, 같은 문장 양쪽 앵커, 실행 취소, 제출 스냅샷 보존, 도움 이후 수행 분류, 재연습의 미노출 오분류 방지, 저장 실패 복구를 중심으로 한다. 접근성 검증은 색을 구분하지 않아도 출처를 이해하고 키보드만으로 표시·관계·설명·제출을 수행하는지 확인한다.

사용성 검증에서는 학생이 ‘지금 무엇을 왜 표시하는지’를 설명하고, 중복 입력 없이 자기 설명을 완성하며, 교사가 실제 구절을 근거로 다음 지도를 결정하는지 관찰한다. 단순 클릭 완료나 표시 개수 증가는 학습 경험의 완료 기준으로 삼지 않는다.
