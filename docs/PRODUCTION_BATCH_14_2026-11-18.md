13차에서는 보관본 만료 뒤 복원만 거부하고 암호화 파일은 남겼다. 이제 실제 검토한 만료 파일을 제거하고, 별도 삭제 원장의 준비·완료 기록으로 중간 장애를 복구한다. 같은 보관본이 다른 경로로 다시 나타나거나 이전 시각을 사용해 복원하려 해도 일반 복원은 거부한다.

## 처리 순서

1. 서버 관리자가 실제 보존 종료·보존 예외·보관본 해시·검토 문서를 확인한다. `--confirmed --holds-cleared`는 실제 검토 이후에만 지정한다. 명령의 플래그가 법률 판단이나 문서 진위를 자동으로 증명하지는 않는다.
2. 알려진 프로젝트 DB, 현재 감사 기준점, 별도 삭제 원장과 복호화 키를 검증한다. 원래 기록의 서명·DB 식별자·순서·공통 앞부분도 검사한다. 다른 DB·변조·틀린 키·아직 보존 중인 파일은 제거하지 않는다.
3. 최소 메타데이터의 `access_archive_purge_prepared` 사건과 로컬 감사 기록을 같은 DB 트랜잭션에 확정하고 별도 원장까지 동기화한다. 여기까지 성공하기 전에는 파일을 제거하지 않는다.
4. 파일 해시를 다시 확인하고 해당 일반 파일을 제거한다. `access_archive_purged`와 완료 감사 기록을 확정·동기화한다. 이미 없어진 파일도 검증된 준비 기록이 있어야 완료 기록을 이어갈 수 있다.
5. 같은 경로에 동일 사본이 다시 생기면 새 작업 식별자로 제거한다. 기존 완료를 그대로 재실행하면 중복 기록을 만들지 않는다. 원장에는 실제 경로·비밀번호·답안 원문을 넣지 않는다.

격리 복원은 보관본 ID를 삭제 원장과 대조한 후 기록을 병합한다. 준비·완료 중 어느 기록이든 해당 ID가 있으면 복원을 거부한다. 이름 변경이나 시각 되돌리기는 허용 근거가 되지 않는다. 새 원장 사건은 학생 삭제 재적용과 함께 복원할 수 있다. 계정·MFA·보호자 재확인과 최신 별도 보존 사본 검증은 유지한다.
