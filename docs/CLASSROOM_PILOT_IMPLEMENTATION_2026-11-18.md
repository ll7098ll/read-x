# 교사 검수·수업 파일럿·문항 난도 보정

> 작성 당시의 설계·조사·구현 기록입니다. 현재 기능과 운영 상태는 최신 현황을 우선합니다. [문서 목차](README.md) · [최신 현황](PROJECT_STATUS.md)


2026년 11월 18일. 편집 검수를 마친 초1~6 진단 172개·성취 확인 288개 과제로 교사가 파일럿을 배정하고, 학생 응답·시간·도움 관찰을 기록해 문항별 난도 보정을 승인하는 흐름을 구현했다.

> 후속 구현으로 승인 보정을 반별 새 진단·코스 선정에 연결할 수 있습니다. [실제 적용·표본 부족 처리·전후 비교](CALIBRATION_APPLICATION_2026-11-18.md)를 참고하세요. 파일럿 원응답 자체를 정규 코스 점수에 합산하는 방식은 아닙니다.

## 실제 수업에서 사용하는 순서

1. 교사가 `#/teacher/classes`의 **교사 검수·수업 파일럿 열기**로 들어간다. 자료 학년·용도·목표를 고르고 **검수·분석**을 연다.
2. 본문과 정답·근거·해설을 살핀 뒤 학년별 난이도, 정답의 유일성, 본문 근거, 해설·채점 준거의 네 항목을 실제로 확인한다. 의견과 함께 사용을 승인하거나 ‘수정 필요’로 남긴다. 승인되지 않은 문항은 새 파일럿에 배정할 수 없다.
3. 승인한 문항과 담당 학생을 선택하고 수업 이름을 적어 배정한다. 한 수업은 같은 자료 학년의 최대 32개 문항, 최대 100명이다. 담당 교사가 학생의 실제 재학 학년과 읽기 수준에 맞는 자료를 고른다. 앱의 자료 학년을 학생의 재학 학년으로 자동 간주하지 않는다. 같은 본문·질문의 중복 배정은 막는다.
4. 학생은 `#/student/classes`의 **배정된 수업 파일럿**에서 시작한다. 선택 답·설명·근거·실제로 받은 도움을 저장하고 이어 풀 수 있다. 초1~2 설명 과제는 글을 쓰는 대신 말로 설명을 요청할 수 있다. 모르는 문항은 ‘미응답’으로 남긴다. 저장한 응답으로 제출하면 수정할 수 없다. 열지 못한 문항은 미도달로 구분한다.
5. 교사는 학생별 정답률·설명 결과·풀이 시간·도움 기록을 살피고 **관찰 기록**을 연다. 실제 도움, 이전 자료 노출, 설명 준거 판단, 관찰 의견을 문항별로 기록한다. 말로 설명한 저학년 과제는 교사가 학생의 실제 말을 받아 적어야 한다. 받아쓰기만 한 경우와 대독·질문 도움을 구분한다. 초시계 등으로 별도 관찰한 시간이 있다면 이유와 함께 보완할 수 있다.
6. 문항의 **검수·분석**에서 첫 독립 수행의 정답률·선지별 선택 수·시간 중앙값·95% 구간·제외 사유를 확인한다. 독립 표본이 20명 이상이면 제안된 난도와 수업 적용 의견을 검토해 **난도 보정 승인**을 누른다.
7. 승인한 난도는 해당 교사의 문항 분석에 표시되고 이후 파일럿 배정본에 함께 저장된다. 관찰 내용·표본이 바뀌면 기존 승인은 ‘자료 변경 · 재검토 필요’가 된다. 새 분석을 확인해 다시 승인한다. 이미 배정된 자료와 당시 보정 이력은 유지한다.

파일럿은 정규 코스와 연결된 별도 관찰 수업이다. 기존 레벨 테스트 결과를 뒤늦게 파일럿 원자료로 자동 합산하지 않으며, 파일럿 응답도 기존 배치 점수·성취 통과 조건에 자동 합산하지 않는다. 학생에게 이미 공개한 진단·학습 글을 새 글로 다시 측정하면 어려움이 가려질 수 있으므로 처음 보는 자료를 우선 배정한다.

## 무엇을 기록하는가

| 기록 | 의미 |
| --- | --- |
| 선택형 정답률 | 제출한 수업에서 실제로 제시된 선택형 문항 중 정답 수 / 제시 수. 미응답은 오답, 미도달은 별도 표시 |
| 설명 과제 결과 | 교사가 준거 충족·추가 지도·관찰 불가로 판단. 선택형 정답률과 따로 표시 |
| 풀이 시간 | 문항별 활동 계측 시간 또는 교사가 보완한 관찰 시간. 시간의 출처와 누락을 보존 |
| 도움 | 학생 보고와 교사 관찰. 도움 없음·질문/힌트·대독·정답/해설 노출·관찰 전/모름을 구별 |
| 이전 자료 노출 | 앱의 과거 자료 노출과 교사 확인을 함께 사용. 새 자료·이미 본 자료·모름 구분 |
| 관찰 맥락 | 학생·반·자료 학년·수업·문항 순서·문항 버전·관찰자·시간·수정 이력 |
| 교사 검수 | 문항 내용 전체의 식별값, 네 가지 점검 결과, 승인/수정 필요, 의견과 이력 |

학생의 ‘도움 없음’ 보고만으로 독립 수행을 확정하지 않는다. 교사가 실제 도움과 이전 노출을 확인해야 보정 표본에 들어간다. 학생이 보고한 도움과 교사가 관찰한 도움 중 더 큰 도움 이력을 유지한다. 이미 기록한 질문 도움·대독·정답 노출을 나중에 ‘도움 없음’으로 바꿔 독립 수행으로 승격할 수 없다. 이미 본 자료로 관찰한 이력도 지우지 않는다. 설명이 맞더라도 선택 답이 틀렸으면 선택형 정답률은 올라가지 않는다.

활동 시간은 서버 시각과 5초 간격의 화면 상태 신호로 누적한다. 창이 보이고 포커스를 가진 동안을 기준으로 하며, 숨김·다른 창으로 이동·15초를 넘는 신호 공백은 긴 시간으로 합산하지 않는다. 여러 탭은 하나의 계측 권한만 사용한다. 학생이 보낸 임의의 ‘풀이 초’ 값을 그대로 저장하지 않는다. 새로고침 후에는 같은 창의 계측을 이어 가도록 탭 세션에 무작위 계측 식별값만 보관하며 답안·정답표를 브라우저 저장소에 넣지 않는다. 따라서 이 값은 초 단위의 완전한 감독 기록이 아니라 수업 관찰을 돕는 근사치이다. 기록이 없는 경우는 0초와 구분한다. 교사가 시간을 보완하면 원래 활동 계측 값과 수정 이력도 보존한다. 시간에는 본문 읽기·문항 읽기·응답이 포함되므로 같은 본문의 첫 문항과 뒤 문항 시간을 단순 비교하지 않는다.

## 난도 보정의 표본과 계산

문항의 학년·내용 버전·배정 교사 범위를 고정해 분석한다. 서로 다른 학년판, 수정 전후의 문항, 다른 교사의 반을 자동으로 섞지 않는다. 교사가 현재 담당하지 않는 학생이나 일반 처리가 정지된 학생은 조회·분석·내려받기에서 제외한다.

한 학생의 **최초 제시 기록을 먼저 선택한 뒤** 독립 표본 조건을 적용한다. 최초 수행이 도움받은 수행이었다면, 뒤의 정답 재응시로 대체하지 않는다. 다음 조건을 모두 만족한 경우만 난도 보정에 사용한다.

- 제출되어 실제로 제시된 문항이다.
- 교사가 도움 없이 읽고 응답한 수행과 첫 자료 노출을 확인했다.
- 이전 파일럿, 진단 응답 또는 코스의 자료 노출 이력이 없다.
- 교사가 문항 오류·관찰 불가로 제외하지 않았다.

제시되었으나 비워 둔 답은 오답으로 포함한다. 미도달은 별도 집계하고 정답률 분모에 넣지 않는다. 선택형은 서버가 당시 정답표로 판단한 정답률을 사용한다. 설명 과제는 교사의 설명 준거 충족 비율을 사용한다. 두 종류의 비율은 같은 의미로 합치지 않는다. 도움·모름·기노출·미검토·관찰 불가 등의 제외 사유는 서로 겹칠 수 있다. 시간이 관찰되지 않은 독립 응답도 정답률에는 사용할 수 있고, 시간 중앙값에서는 제외해 시간 관찰 인원을 따로 표시한다.

정답률 `p = 정답 수 / 독립 표본 수`와 Wilson 방식의 95% 구간을 제공한다. 정답률이 높을수록 쉬운 문항이다. 다음 구간과 20명 기준은 이번 파일럿의 운영 규칙이며 표준화된 교육 규준이나 검증된 최소 표본 수가 아니다.

| 독립 표본 | 처리 |
| --- | --- |
| 0~19명 | 정답률·참고 구간은 관찰값으로 표시, 난도 보정 승인은 잠금 |
| 20명 이상·정답률 80% 이상 | 입문 제안 |
| 20명 이상·정답률 50% 이상 80% 미만 | 기본 제안 |
| 20명 이상·정답률 50% 미만 | 도전 제안 |

구간이 50%·80% 경계를 걸치면 불확실성을 표시한다. 교사가 표본·도움·노출·구간을 실제 검토하고 의견을 남겨야 승인된다. 표본의 선택 편향, 같은 학급 학생 간 유사성, 지원형·확장형 배정의 차이를 이 계산이 해결하지는 않는다. 같은 학생의 여러 응답을 새로운 학생 수로 세지 않는다. 이항모형의 구간은 참고 값이며 전국 수준 추론이나 IRT 척도·학년 등가 점수를 제공하지 않는다. 문항이 쉬워졌다는 표시만으로 정답·본문·배치 임계값을 자동 수정하지 않는다.

NAEP의 [고전 문항 분석 설명](https://nces.ed.gov/nationsreportcard/tdw/analysis/initial_classical_dich.aspx)은 문항별 정답 비율 등의 분석을 소개한다. 본 구현의 제시 문항 분모와 보정 구간은 프로젝트 운영 선택이며 NAEP의 전체 설계와 동일하지 않다. [OHID 비율·구간 계산 안내](https://fingertips.phe.org.uk/static-reports/public-health-technical-guidance/Basic_statistics/Proportions.html)의 Wilson 계산식을 참고했다.

## 기존 학습과 노출 기록

파일럿이 정규 학습의 독립 성취를 부풀리지 않도록 연결했다. 파일럿 전에 정규 코스에서 노출된 확인 자료는 파일럿 보정의 새 자료 표본에서 제외한다. 파일럿에서 이미 본 확인 자료 역시 정규 코스의 새 글 독립 확인 후보에서 건너뛴다. 남은 미노출 자료가 없으면 기존대로 교사에게 새 자료를 요청한다. 파일럿에서 본 진단 자료로 정규 진단을 시작하면 교사 배치 검토에 기노출 안내를 표시한다.

## 저장·조회·검증

SQLite의 `pilot_sessions`, `pilot_runs`, `pilot_item_reviews`, `pilot_calibrations`에 배정본·응답·검수·보정을 저장한다. 문항 내용 전체의 식별값과 승인본을 보관해 수정 전후 표본을 합치지 않는다. 동시 편집은 버전 충돌을 알리고 배정 재시도는 중복 수업을 만들지 않는다. 학생에게는 자기 배정·응답·시간만 전달하고 정답표·해설·교사 검수 원문·보정 통계는 전달하지 않는다.

교사는 **파일럿 관찰·분석 JSON 내려받기**로 담당 범위의 학생별 요약·문항별 지표·관찰 행을 저장할 수 있다. 해당 동작과 검수·보정에는 기존 접속·처리 기록이 남는다. 개인정보 검토 사본에도 학생 본인의 파일럿 기록을 선택할 수 있으며 문항 정답표와 타인의 인증정보는 제외한다. 기존 일반 처리정지와 담당 반 제한을 따른다.

회귀 검사: `webapp`에서 `node --test server/pilot-service.test.mjs server/course-service.test.mjs server/placement-service.test.mjs` 및 `npm run build`.

화면 검사: 가상 메모리 DB 전용 `webapp/scripts/preview-pilot-ui.mjs`를 실행한 뒤 프로젝트 루트에서 `python scripts/verify_classroom_pilot_browser.py`. 이 검사는 가상 학생 22명으로 독립 20명·도움 1명·관찰 전 1명을 만들고 교사 승인, 저장 후 이어 풀기, 활동 시간, 관찰, 보정 승인, 새 배정본, 자료 변경 후 재검토, JSON 내려받기와 모바일 화면을 검증한다. 실학생이나 운영 DB에 시험 결과를 쓰지 않는다. 결과는 `output/classroom-pilot-2026-11-18`에 남긴다.
