**제작 단위는 학생이 한 목표를 배우고 새 자료에서 수행하는지 확인할 수 있는 완결된 수업 묶음이다.** 지문과 문제에 사고 시범, 단계별 도움, 쓰기, 보충 활동, 평가 준거, 교사 지도안, 학부모 설명을 함께 붙인다. 초1~6 수업과 모의고사를 모두 운영한다는 [운영 전환 계획](PRODUCTION_IMPLEMENTATION_PLAN_2026-11-14.md)을 콘텐츠 물량과 제작 절차로 구체화한다.

생성·수정에 사용하는 세부 기준과 프롬프트는 [콘텐츠 생성 규칙](CONTENT_AUTHORING_RULES.md)에 둔다. 아래 수량 중 현재 보유량과 신규 제작 목표는 구분한다.

## 4 학년과 목표에 따른 제작 설계

수업 편성표는 학년 × 대표 목표 × 교과 개념 × 글 구조 × 사용 목적을 연결한다. 목표 ID는 기존 원장을 재사용한다. 지문을 추가할 때 목표 ID를 새로 만들지 않는다. 공식 성취기준, 프로젝트 목표, 교과 개념을 서로 다른 필드로 관리한다.

읽기 V 계열은 대상·정보·관계·판단을 실제로 찾고 설명하게 한다. 쓰기 W 계열은 해당 목표가 요구하는 조직·문장·근거·고쳐쓰기를 수행하게 한다. 공통 A1~A6는 같은 명칭이라도 학년별 원장의 수행 조건에 따라 자료와 행동을 달리한다.

교과 배치는 검증된 개념부터 정하고, 학년군 기준을 임의로 특정 학년·학기의 공식 배치라고 표시하지 않는다. 예비 편성표에는 편집 배치와 공식 확인을 구분한다. 국어 읽기를 연습하는 글에 교과 배경지식을 과도하게 요구하지 않도록 필요한 설명을 본문에 둔다.

동일한 수업 안의 세 수준은 같은 대표 목표를 유지한다. 핵심 정보와 관계는 도움글에도 있어야 하며, 기준글은 사례를 보강하고 도전글은 조건·예외·자료 관계를 확장한다. 확장으로 새로운 기능을 요구하면 보조 목표와 문항을 별도 표시한다. 현재 앱이 수준별 문단을 누적해서 보여 주는 구조인 점을 생성 규칙에 반영한다.

| 8 | 제한된 현장 확인 | 학년·인원·지원 조건·시간·관찰 메모 | 모호한 발문과 조작·읽기 부담에 따른 수정 반영 |
| 9 | 운영 승인과 버전 고정 | 게시 목록·콘텐츠 해시·승인 기록 | 필요한 모든 구성품이 승인된 버전으로 연결됨 |

AI는 집필·재작성·누락 탐지·검토 의견을 만든다. 실제 교사 검토나 학생 관찰을 수행했다고 생성하지 않는다. 작성과 재검토 요청을 분리하되 두 AI 결과를 독립 교사 승인으로 표시하지 않는다. 사실 원문, 정답 유일성, 여러 서술 답의 수용 범위, 어린이에게 자연스러운 표현은 내용 검토자가 판정한다.

검수 상태는 초안 → 자동 검사 통과 → 교사 검토 통과 → 파일럿 확인 → 운영 승인 → 게시로 관리한다. 파일럿 참여용 배정은 교사 검토 통과 자료에만 허용하고 일반 운영 게시와 구분한다. 새 학년·활동 유형·시험지는 직접 관찰하며, 검증된 형식의 반복 제작은 사전에 정한 표본을 관찰하고 그 범위를 기록한다. 표본 관찰을 모든 지문의 난도 보정 완료라고 표시하지 않는다.

내용 반려는 수정 후 영향을 받는 단계부터 재검토한다. 게시된 자료를 직접 덮어쓰지 않고 새 버전을 만든다. 정답 변경은 기존 응시의 재채점과 리포트 정정 절차로 연결한다.

## 6 실행 순서와 처리량

### 첫 제작 묶음

각 학년 2개씩 총 12개를 먼저 완성한다. 구성은 학년별 정규 1개와 공통기초 1개이며, 정규 6개 중 최소 2개는 W 계열로 편성한다. 지문·표·그림, 선택형·서술형, 쓰기 수정, 근거 표시가 골고루 들어가도록 정한다. 실제 목표 ID는 원장에서 의뢰서를 만들 때 고정한다.

이 12개에 B·C 각 12개, 보충 12개, 지도안과 학부모 안내 각 12개를 붙인다. 앱에서 시범에 표시한 구절, 근거 선택, 서술 답 검토, 새로운 자료의 노출 상태까지 확인해야 한 묶음이 완료된다.

| 단계 | 작업량과 순서 | 완료 기준 |
| --- | --- | --- |
| 준비 | 132개 목표 연결표, 기존 144편 판정 목록, 중복·상태·길이 정비 목록 | 빠진 목표와 재사용·신작 범위가 보임 |
| 대표 제작 | 위 12개 완결 수업과 연결 자료 | 규칙·데이터 구조·실제 수업 가능성을 확인 |
| 수업 확대 | 나머지 120개를 24개씩 5묶음으로 제작 | 전체 132개 목표의 수업·B·C·보충·지도안 연결 |
| 평가 제작 | 학년별 출제표 → 01회 6종 → 02회 6종과 시험 후 확인 36개 | 총 12종·224문항의 별도 검수 및 비공개 편성 |
| 현장 수정 | 각 학년의 대표 활동과 시험 운영, 오류 반영 | 출시 대상의 중대 내용 오류와 수행 장애 해결 |
| 운영 공급 | 승인한 묶음만 배포하고 수정 요청 추적 | 수업 배정과 과거 응시에서 정확한 버전 조회 |

대표 제작은 이후 132개에 포함된다. 수업 확대와 평가 제작은 작업 일정상 병행할 수 있지만, 검수 대기량이 늘면 초안 추가보다 반려 수정과 승인 처리를 먼저 한다.

### 일정 산정 방식

첫 12개에서 초안 작성 시간, 검토 시간, 수정 횟수, 최초 통과율, 최종 승인 처리량을 기록한다. 일정은 AI 생성 속도보다 최종 승인 속도로 계산한다.

- 수업 잔여 기간 = 남은 완결 수업 수 ÷ 주당 최종 승인 수업 수.
- 시험 잔여 기간 = 남은 시험지 수 ÷ 주당 최종 승인 시험지 수.
- 같은 교사가 두 작업을 검토하면 검토 시간을 나눠 계산하고 동시 처리량을 중복 배정하지 않는다.

예를 들어 대표 제작 이후 주당 12개 수업을 최종 승인할 수 있다면 남은 120개에 10주가 필요하다. 주당 6개면 20주다. B·C·보충·지도안 검토까지 포함한 처리량이며, 시험과 현장 수정 시간은 별도로 잡는다. 기존 개발 계획의 기간이 콘텐츠 제작 기간을 자동으로 보장하지 않는다.

필요 역할은 교육 편집 책임자, 집필 담당, 학년별 내용 검토 교사, 콘텐츠 데이터·화면 검증 담당이다. 한 사람이 역할을 겸할 수 있어도 본인 집필을 독립 검토했다고 기록하지 않는다.

## 7 원장과 앱 연결 계획

다음 위치는 기존 경로를 활용하거나 추가할 제안이다. 새 생성기와 검증기를 이번 계획 작성에서 구현한 것은 아니다.

수업 데이터에는 문장 단위 ID, 수준별 문항과 근거, 실질적인 루브릭, 노출 이력, 승인 상태를 전달하는 계약이 필요하다. 현행 타입으로 표현할 수 없는 필드는 버전 있는 스키마로 확장한 뒤 빌더와 화면을 함께 바꾼다. 데이터 원장과 생성 결과를 각각 수정하는 이중 관리는 피한다.

진행판의 첫 숫자는 생성 파일 수가 아니라 완결 수업 승인 수 / 132, 승인 시험지 수 / 12, B·C 연결 충족 목표 수 / 132다. 제외 지문·중복·수정 중 자료와 신규 승인 자료를 구분한다.

## 8 공급 확대 기준

최초 운영 이후에는 같은 목표의 다른 교과·소재, 재확인용 예비 자료, 부족한 장르를 늘린다. 이미 본 B·C는 해당 학생에게 새 자료 확인으로 재사용하지 않는다. 적합한 예비 자료가 없으면 교사에게 추가 확인 대기로 알리고 새 자료를 공급한다.

개념 후보 826개를 한 번에 전부 생성하지 않는다. 실제 교과 배치와 목표 연결을 검증한 개념을 우선순위에 올린다. 배정 수요가 많은 목표, 승인 자료가 적은 목표, 자주 반려되는 유형, 새 자료가 소진된 목표 순으로 보충한다.

확대 물량은 승인한 개념 수와 실제 수업 수요로 계산한다. 제목 변경, 인물명 교체, 수준별 확장, 동일 자료의 다른 문제는 각각 신작 지문으로 집계하지 않는다. 목표 충족·자료 다양성·오류 수정 속도가 확보된 뒤 공급량을 늘린다.
