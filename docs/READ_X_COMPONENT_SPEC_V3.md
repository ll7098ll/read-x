## 재사용 소스

- `ReadXBrand.tsx`: 전체 앱 공통 CI.
- `readXSystem.ts`: 컬러 라벨·학습 단계 문구.
- `ReadingMethodDemo.tsx`: 랜딩과 킷에서 사용하는 동일한 짧은 시범.
- `BrandKit.tsx`: 컴포넌트 상태와 역할별 화면 예시.
- `DesignSystem.tsx`: 기존 Dialog / PageHeading / EmptyState / ThinkingPath / BrandGuide 유지·연결.
- `read-x-tokens.css`: 토큰 원본.
- `read-x.css`: v3 공통 클래스와 킷, 기존 CSS 토큰 호환 연결.

클래스 기반 조작 UI는 `readx-button`, `readx-feedback`, `readx-choice-list`, `readx-reader-spec` 등을 재사용한다. 각 클래스가 모든 기존 화면에 자동 적용된다고 가정하지 않는다. 새 화면에서 기존 고정색 클래스를 추가하지 않는다.

## 화면별 구조

### 1. 학생 홈

상단 공통 브랜드/공간 이름 → 오늘의 읽기 방법 → 이어할 수업 한 개 → 진행 단계 → 읽기 기록/낱말 모음.

- 학생이 처음 들어오면 ‘시범 보기’를 중심 행동으로 제시.
- 이어하기가 있으면 수업 제목·마지막 활동·저장 상태와 함께 제시.
- 경쟁 순위와 시험 점수를 학습의 대표 정보로 올리지 않음.
- 남은 시간은 근거 있는 추정이 있을 때만 표시.

### 2. 읽기 스튜디오

브랜드 / 수업 이름 / 목록 복귀 → 학습 단계 → 지문 + 활동 → 저장 상태 / 다음 행동.

- 900px 초과: 지문 60%, 활동 40%를 기본으로 하되 지문 가독 폭 제한.
- 900px 이하: 지문/활동 전환. 두 패널의 state를 유지하며 선택과 답안 보존.
- 고정 하단 버튼이 본문을 가리지 않도록 하단 여백 확보.
- 근거를 선택한 뒤 이유를 쓰게 연결. 위치 힌트, 관계 질문, 시범을 구분.
- 도움 사용은 학습자의 선택으로 기록. 도움 사용을 감점이나 실패로 표시하지 않음.
- 음성·낭독이 있으면 재생/정지와 현재 읽는 위치를 명시. 사용자 조작으로 시작.

### 3. 활동 마무리

오늘 쓴 방법 → 내가 고른 근거 → 내가 쓴 문장 → 받은 도움 → 다음에 해 볼 일.

응답 완료, 교사 검토 완료, 새로운 글에서 독립 적용을 서로 다른 상태로 관리한다. 수업 완료만으로 ‘완전 숙련’을 표시하지 않는다.

### 4. 교사 수업실

오늘 목표 / 수업 배정 → 학생별 관찰 목록 → 근거·응답 확인 → 다음 지도.

학생의 현재 기록, 도움 사용, 교사 검토 상태가 함께 보여야 한다. 초기·미수집 데이터를 0점으로 그리지 않는다. 교사는 학생별 원문과 응답을 확인한 뒤 다음 질문을 선택한다.

### 5. 보호자 읽기 기록

배운 방법 한 문장 → 학생이 실제 작성한 문장 → 도움을 받은 부분 → 다음 연습 → 가정에서 나눌 질문.

실제 발화와 작성 예시를 섞지 않는다. 킷 예시는 ‘화면 예시’로 표시. 출처가 없는 비교 점수와 성장 퍼센트를 만들지 않는다.

### 6. 관리·자료실

검색과 필터 → 콘텐츠/반/계정 목록 → 상세 검토 → 명확한 저장·공개 상태. 브랜드 컬러는 업무 상태 의미와 충돌하지 않게 사용한다.

## 상태와 복구 매트릭스

| 상황 | 보여줄 내용 | 보존할 정보 | 다음 행동 |
|---|---|---|---|
| 로딩 | 무엇을 불러오는지 | 기존 입력·선택 | 완료 또는 명시적 재시도 |
| 빈 수업 | 아직 배정된 수업 없음 | 기존 기록 | 시범 / 자료 둘러보기 |
| 입력 오류 | 고칠 항목과 예시 | 작성 초안 | 해당 입력으로 초점 |
| 저장 실패 | 저장 실패와 현재 보존 범위 | 메모리 초안, 가능한 로컬 임시본 | 연결 확인 / 다시 저장 |
| 제출 완료 | 제출 시점과 검토 상태 | 제출한 응답 | 기록 보기 |
| 교사 검토 대기 | 아직 피드백이 없음 | 학생 응답 | 다른 읽기 / 기록 확인 |
| 읽기 도움 요청 | 위치 힌트 → 관계 질문 → 시범 | 학생의 이전 선택 | 다시 시도 |
| 새 지문으로 이동 | 새 글에 적용하는 목표 | 이전 수업 기록 | 독립 시도 |

## 접근성과 검증 기준

- 문서 순서와 시각 순서 일치, 제목 단계 h1→h2→h3.
- 탐색/그룹에 이름 부여, 실제 버튼·링크·select 사용.
- 장식선과 조작 경계 구별. 주요 본문/버튼 색상 대비를 계산하고 기록.
- 키보드로 선택·입력·도움·닫기 가능. 모달 Escape와 초점 복귀 확인.
- 390px / 768px / 1440px 확인, 화면 가로 넘침·끊어진 문구·가린 CTA 점검.
- 크기 확대·야간·단계 변경에도 입력과 근거 선택 유지.
- 공개 미리보기에는 실제 계정/실제 학습 기록과 구분한 예시 표시.
- 자동 빌드/기존 테스트와 수동 화면 확인을 구분해 결과 기록. 전체 접근성 인증이나 학습 효과 검증으로 표현하지 않음.

## 적용 구분

v3에서 구현: 공통 CI, CSS 테마 연결, 첫 화면, 짧은 시범, 디자인 가이드, 인터랙티브 킷과 에셋 다운로드.

v3에서 설계 기준 제공: 전체 학생·교사·보호자 IA와 공통 상태 계약.

순차 이행: 기존 수업 스튜디오별 4단계 흐름, 모든 고정색 치환, 보고서와 상태 컴포넌트 통합. 이미 있는 저장·계정·평가 엔진에 실제 상태를 연결하고 나서 해당 화면의 이행 완료를 표시한다.
