# 학원 실사용을 위한 개인정보 법률 보안 운영 계획

<!-- readx-document-context -->
> 작성 당시의 설계·조사·구현 기록입니다. 현재 기능과 운영 상태는 최신 현황을 우선합니다. [문서 목차](README.md) · [최신 현황](PROJECT_STATUS.md)


2026년 11월 14일. 운영 전제는 사용자가 직접 운영하는 학원, 교사가 등록한 뒤 보호자가 동의·연결하는 흐름, 국내 서버·저장소 운영이다. 결제와 문자는 도입 희망 범위에 포함한다. 실제 학원 운영 명의·책임자·연락처·서버 업체·PG·문자 업체는 아직 확정되지 않았다.

**실사용 완료는 기능 동작뿐 아니라 적법한 개인정보 처리, 안전한 배포와 운영, 사고 대응, 보관·파기, 유지보수와 증거까지 갖춘 상태를 뜻한다. 현재 코드는 가상 자료로 검증 중이며 실제 학생 개인정보 운영 준비는 완료되지 않았다.**

## 1. 운영 책임과 적용 법령

직접 운영하는 학원이 어떤 목적으로 어떤 자료를 처리하는지 정하는 운영 구조로 설계한다. 외부 개발·호스팅·백업·문자·결제 사업자의 역할과 접근 범위는 계약별로 구분한다. 개발자가 모든 자료를 자유롭게 열람하는 권한을 기본으로 두지 않는다.

실제 운영 명의, 학원 등록·사업자 정보, 개인정보 보호책임자, 보호자 문의 창구, 장애·보안 담당자와 대체 담당자를 확정한다. 관할 교육청의 학원 운영·장부·교습비 관련 요건과 온라인 결제·판매 방식에 따라 적용될 소비자 보호·거래·세무 요건도 별도 검토한다. [현행 학원법](https://www.law.go.kr/LSW/lsInfoP.do?ancYnChk=0&chrClsCd=010202&efYd=20261001&lsiSeq=285147)을 검토 기준으로 두되 지역과 거래 방식이 정해지기 전 적용 결과를 확정하지 않는다.

보안 인증·영향평가 등의 의무 대상 여부는 실제 업종·규모·처리 내역을 기준으로 확인한다. 내부 체크리스트 통과를 법률 적합성 확인이나 외부 인증으로 표시하지 않는다.

## 3. 교사 등록과 아동·보호자 절차

만 14세 미만 아동의 개인정보 처리에 동의가 필요한 경우 법정대리인의 동의와 확인이 필요하고, 아동에게는 이해하기 쉬운 안내가 필요하다. [개인정보 보호법 제22조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398521)

교사 선등록에 필요한 항목과 적법 근거를 먼저 정한다. 등록 단계에서 기존 수강 계약 등 별도 근거가 있는 처리와 보호자 동의를 근거로 하는 처리를 구분한다. 계정 생성이나 보호자 아이디 연결을 법정대리인 확인·동의 완료로 대체하지 않는다.

구현 흐름은 최소 정보의 등록 대기 → 보호자 안내 → 보호자 및 법정대리인 관계 확인 → 고지 항목별 동의 → 학습 계정 활성 → 변경·철회·재동의다. 실제로 사용할 본인 확인 방법은 업체·비용·보관 정보와 함께 정한다. 운영자가 확인을 생략하거나 과거 동의를 임의로 입력하는 경로도 통제한다.

필수 처리와 선택적 광고·추가 이용은 나누고, 선택 동의 거절 때문에 기본 학습을 막지 않도록 검토한다. 동의 문구·버전·대상 아동·확인 방법·시각·행위자를 기록한다. 법정대리인 변경, 복수 보호자, 양육권 분쟁, 동의 철회와 학생의 연령 변화에 대한 담당자 절차를 둔다.

다섯 번째 개발 묶음에서 운영자의 확인 기록, 버전별 안내문·동의 사건, 필수·선택 분리, 동의에 따른 학생 이용과 보호자 연결, 철회·확인 해제·안내문 변경 시 접근 차단을 구현했다. 기존 연결은 동의로 추정하지 않는다. 실제 본인·법정대리인 확인 절차와 증빙 진위 확인, 안내문의 적법성 검토·권리 행사·파기·변조 방지는 아직 완료되지 않았다. 자세한 구현과 한계는 [다섯 번째 개발 기록](PRODUCTION_BATCH_05_2026-11-14.md)을 따른다.

## 4. 방침 계약 권리 행사

실제 처리와 일치하는 개인정보 처리방침, 보호자·아동 안내, 동의 항목, 이용조건, 위탁 관련 문서를 만든다. 공개 문서에는 실제 운영 명의와 문의 창구를 넣고, 미정 내용을 완료된 것처럼 공개하지 않는다. 방침은 로그인 전에도 볼 수 있어야 하고 이전 버전과 적용 시점을 보존한다. [개인정보보호위원회의 2026 처리방침 작성지침](https://www.privacy.go.kr/front/bbs/bbsView.do?bbsNo=BBSMSTR_000000000049&bbscttNo=20885)을 작성 기준으로 사용한다.

열람·정정·삭제·처리정지·철회 요청은 본인·법정대리인 확인 → 대상 범위 결정 → 타 학생 정보 분리 → 처리 또는 제한 사유 안내 → 처리 이력 보존으로 구현한다. 기한과 예외는 실제 적용 법령을 확인해 정한다. 출력물과 다운로드에도 다른 자녀·학생의 정보가 섞이지 않아야 한다.

외부 업체별 업무, 제공·위탁 관계, 재위탁, 처리 위치, 접근 인력, 사고 통보, 계약 종료 시 반환·파기, 점검 책임을 정리한다. 계약 체결과 책임자 지정은 실제 운영 당사자의 검토·실행이 필요하다.

## 5. 보관과 파기

계정·학습·출석·상담·동의·접속기록·거래·백업을 같은 기간으로 무기한 보관하지 않는다. 불필요해진 개인정보는 파기하고 다른 법령에 따라 보존해야 하는 자료는 구분한다. [개인정보 보호법 제21조](https://law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029334977)

자료별 보유기간과 근거, 종료 이벤트, 법정 보존 예외, 분쟁 보존, 접근 제한, 파기 실행자와 검증 결과를 관리한다. 탈퇴·퇴원·삭제 요청 때 수업 DB·공개본·검색·캐시·미전송 큐·파일·백업까지 처리 흐름을 정의한다. 백업은 만료 정책을 적용하고, 복원 시 삭제·철회 이력을 다시 적용하여 삭제 자료나 철회한 연결을 되살리지 않는다.

현재 휴원·퇴원은 접속 제어와 기록 보존이다. 이를 개인정보 파기 완료로 취급하지 않는다. 영구 삭제는 대상과 보존 예외를 검토한 구체적인 작업으로 실행하며, 검증 자료도 같은 기준으로 관리한다.

현재는 역할·반 권한, 비밀번호 해시·세션·복구, 공개 통제가 일부 구현되어 있다. [기기 초안 보호](PRODUCTION_BATCH_06_2026-11-14.md)에서 실제 읽기·평가의 임시 초안을 암호화하고 본인 인증으로 복구하며 계정 변경·로그아웃·늦은 응답을 제어했다. 이는 실제 단말 분실·오프라인 종료·XSS까지 해결한 결과가 아니다. 추가 인증, 개인정보 열람·출력 접속기록의 별도 보호, 서버 저장소 암호화·키 분리 관리, 실제 운영망 점검은 아직 완료되지 않았다.

## 7. 국내 운영과 외부 통신

국내 서버를 선택하더라도 CDN·로그·백업·지원 인력·문자·PG·외부 AI까지 처리 위치를 확인한다. 개인정보의 국외 제공·조회·위탁·보관은 별도 검토 대상이다. [개인정보 보호법 제28조의8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034292881)

국내 운영·DB·파일·백업·로그 위치, 재위탁자, 관리자 접속 위치를 계약과 설정·실측으로 확인한다. 외부 도메인 자동 요청을 목록화하고 필요한 곳만 허용한다. 개발·검증·운영과 실제 자료의 반입·반출을 분리한다.

이번 작업에서 첫 화면이 자동 호출하던 외부 글꼴 CDN 두 곳을 제거했다. 기본 글꼴은 기기의 설치 글꼴을 사용한다. 읽어주기는 브라우저가 로컬 음성으로 보고하는 한국어 음성만 명시적으로 선택하며 없으면 외부 기본 음성으로 대체하지 않는다. 이는 외부 요청을 줄이는 조치이며 기기·운영체제의 전체 통신을 확인한 결과는 아니다. 실제 기기 네트워크 검증은 남아 있다.

## 8. 결제 문자 외부 AI

결제는 먼저 테스트 환경에서 주문·서버 금액 확인·결제 성공 검증·서명 확인·중복 웹훅·취소·부분 환불·실패·정산 불일치를 검증한다. PG 결제창을 사용하고 카드 민감정보는 직접 취급하지 않는다. 교습비·환불·고지·영수증·법정 거래 기록은 실제 상품과 학원 운영 방식에 맞춰 법률·세무 검토를 거친다. 유료 업체 계약·실제 결제는 별도 실행 단계다.

문자는 수업·결제 등의 업무 안내와 광고를 분리한다. 보호자 연락처 확인, 목적별 수신 상태, 수신 거부·철회, 광고·야간 발송의 적용 요건, 발신번호와 템플릿, 중복·오발송 방지, 실패·재시도·발송 기록을 설계한다. 점수·답안·상담 내용은 문자에 직접 넣지 않고 로그인 후 확인하도록 한다. 실제 업체와 계약·법적 고지가 확정되기 전에는 발송 기능을 활성화하지 않는다.

외부 AI는 학생 원문·교사 상담을 자동 전송하거나 학습 데이터로 제공하는 기능을 기본으로 두지 않는다. 도입 시 목적·제공 범위·업체 저장·학습 이용·국외 처리와 사람의 검토를 별도로 정한다. 분석 수치로 검증되지 않은 능력·등급을 확정하지 않는다.

## 9. 운영 유지보수와 사고 대응

장애·저장 실패·계정 공격·대량 다운로드의 관찰과 경보, 담당자 인계, 업데이트·의존성 목록·취약점 점검, 변경 승인·검증 서버·배포·롤백을 운영 절차에 포함한다. 취약점 수가 0이라고 전체 보안이 안전한 것으로 판정하지 않는다.

백업은 암호화·접근 제한·별도 보관·주기적 복원을 검증한다. 최대 1시간 이전 데이터로 복구·4시간 내 서비스 복원은 초기 목표이며, 실제 업체·비용·복구 훈련 결과로 확정한다. 서버 장애, DB 손상, 랜섬웨어, 키 유실, 실수 삭제, 기기 분실과 담당자 부재를 훈련한다.

사고 대응은 탐지 → 내부 보고 → 확산 차단·권한 회수 → 증거 보전 → 영향 평가 → 통지·신고 판단·이행 → 복구·재발 방지로 정리한다. 신고 대상·기산점·예외를 실제 사건에 맞게 판단한다. 개인정보보호위원회는 일정 규모 유출, 민감·고유식별정보 유출, 외부 불법 접근에 의한 유출 등의 신고 기준과 72시간 기한을 안내한다. [공식 유출신고 안내](https://pipc.go.kr/np/default/page.do?mCode=D030040000)
