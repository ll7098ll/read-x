2026년 11월 14일. 실제 읽기 수행과 시험의 미전송 답안을 브라우저 `localStorage`에 평문으로 보관하던 경로를 변경했다. 실제 운영 승인이나 전체 보안 완료를 뜻하지 않으며 DEVICE-01 등 23개 통제는 검토 대기 상태다.

2026년 11월 15일 보완: 아래의 401·자동 재인증 시 정리 동작은 [일곱 번째 기록](PRODUCTION_BATCH_07_2026-11-15.md)으로 갱신했다. 유효한 암호문을 잠그고 본인 재인증 뒤 복구하며, 명시적 로그아웃·계정 변경·키 변경에서는 정리한다.

## 구현

- 실제 계정의 읽기 초안·글·충돌 보관본·시험 미전송 답안·표시·위치는 AES-256-GCM으로 암호화한다. 매 암호화에 임의의 96비트 nonce를 사용하고 레코드 경로·버전·키 ID·복구 유효기간을 인증 데이터에 결합한다. 다른 레코드나 계정으로 옮기거나 내용을 변경한 암호문은 복구하지 않는다.
- 키는 로그인한 계정 자신의 인증된 서버 요청으로만 받는다. 브라우저에는 추출 불가능한 CryptoKey를 메모리에 두며 키 원문을 localStorage·sessionStorage·IndexedDB에 저장하지 않는다. 키 API에는 학생의 글이나 답안을 전송하지 않는다. 명단·세션·대시보드 응답에 키를 넣지 않는다.
- 기존 평문 초안은 인증한 본인 소유의 경로만 암호화 저장한 뒤 평문을 제거한다. 다른 계정의 초안은 계정 변경 시 제거한다. 암호화 저장에 실패하면 새 평문 저장으로 대체하지 않고 서버 저장과 화면의 입력 보존 상태를 안내한다. 이전 평문 이관이 실패하면 자동 제거를 완료했다고 주장하지 않는다.
- 초안 읽기는 비동기적으로 끝난 뒤 학생 입력을 연다. 초기 빈 상태가 복구할 초안을 덮어쓰지 않도록 제어한다. 저장 큐는 입력 당시의 사본을 순서대로 암호화하며 제출 후 제거가 앞선 암호화를 기다린다. 로그아웃 중 늦게 도착한 키·암호화 작업은 초안을 다시 만들 수 없다.
- 로그아웃·계정 변경·401 응답 시 기기의 private 초안과 메모리 키를 정리하고 다른 탭에도 전달한다. 늦게 도착한 이전 요청의 응답은 현재 계정 화면을 복원하지 못한다. 비밀번호 변경·복구·계정 비활성화·동의 철회·보호자 확인 해제·안내문 변경 등의 해당 경로는 서버의 기기 키를 무효화한다.
- 연결이 끊긴 로그아웃도 화면의 계정 정보와 기기 초안을 먼저 지운다. 서버 로그아웃의 미완료 표시를 남기고, 다음 API 접근에서 종료를 처리한 뒤 다른 요청을 보낸다. 표시에는 대상 계정의 가명 ID만 담고 이름·답·비밀번호·세션 토큰을 담지 않는다. 다른 탭에서 계정이 변경된 경우 이전 계정을 대상으로 한 재시도가 새 계정 세션을 종료하지 않도록 서버가 대상 ID를 확인한다. 서버 로그아웃은 이미 만료된 세션에도 반복 가능하다.
- 저장 완료 문구는 서버 저장과 암호화 기기 보관을 구분한다. 복구·암호화·기기 용량·연결 실패를 숨기지 않는다. 시험 마감 후에는 서버에 도착한 답안으로 채점하고 미전송 초안의 존재를 안내한다.

공개 체험 모드는 가상 자료의 브라우저 저장을 유지한다. 실제 계정과 연결되지 않으며 실명·연락처·실제 학생 기록 입력 금지와 기기에 남을 수 있음을 안내한다. 공개 체험이 암호화 운영 저장소라고 표시하지 않는다.

## 검사와 제한

암호화 실동작 검사 5개, 계정·탭·지연 응답·오프라인 로그아웃·기존 초안 이관을 연결한 클라이언트 검사, 실제 HTTP의 본인 키 범위·비밀 비노출·철회/비밀번호 변경 후 키 교체·로그아웃 재시도 검사를 추가했다. 전체 검사는 UI·학습 도메인 80개와 서버·운영 38개, 합계 118개가 통과했다. 최종 결과는 `output/device-drafts-build-2026-11-14.log`에 기록했다. 검증한 공개 사본도 Sites 버전 5로 배포했으며 [사이트 반영 기록](SITE_RELEASE_2026-11-14.md)에 실행 범위를 구분했다.

복구 유효기간은 마지막 저장부터 12시간이다. 만료한 암호문은 읽기·정리·새 저장 시 삭제하며 로그아웃·제출 시에도 제거한다. 브라우저가 닫혀 있으면 서버가 기기 파일을 삭제할 수 없으므로, 12시간 경과 시점에 물리적으로 삭제되었다는 보장은 아니다. 데이터 파기 정책·기기 분실·포렌식 복구·백업 관리는 별도 검토해야 한다.

현재 서버의 기기 키는 계정 원장의 SQLite JSON에 들어 있다. 서버 DB 자체의 자료 암호화·키 분리 보관·백업·보존기간·키 접근 감사는 아직 완료되지 않았다. 암호화 초안을 처음 복구하거나 브라우저를 다시 열었을 때는 유효한 서버 인증과 연결이 필요하다. 키가 무효화된 예전 기기 초안은 복구할 수 없으며 마지막으로 확인된 서버 저장본을 사용한다.

암호화는 잠긴 저장 데이터의 노출을 줄이는 조치다. 로그인한 상태의 XSS·악성 확장 프로그램·키로거·화면 촬영·잠기지 않은 공용 기기까지 방어하지 않는다. 오프라인에서는 HttpOnly 서버 세션을 즉시 원격 폐기할 수 없으며 복구 후 종료 재시도와 별도로 OS 잠금·쿠키·단말 운영 절차가 필요하다. 기기 저장이 차단된 브라우저에서는 종료 대기 표시의 재시작 후 유지도 보장되지 않는다.
