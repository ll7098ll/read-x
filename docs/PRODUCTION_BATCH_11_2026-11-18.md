## 실제 제거 범위

현재 로그인 비밀·MFA·복구·기기 초안 키를 제거하고 대상 로그인을 종료한다. 원장 명단에는 새 로그인이 불가능한 최소 삭제 계정 표식만 남긴다. 이름·아이디 원문과 비밀번호 등을 이 표식에 보존하지 않는다. 별도 보존하는 계정 사본에도 비밀번호·MFA 비밀·복구 코드·기기 키를 복사하지 않는다. 삭제된 계정의 일반 수정·복구·재활성화 경로는 차단한다.

대상 학생의 읽기 원장·공개 사본·진단·학습 코스·파일럿 원자료, 시험·보충 수행, 출결·상담·반 소속, 동의·확인 원장과 이전 권리 요청·사본은 검토한 결정대로 별도 암호화 사본을 만들거나 보존하지 않고 운영 표에서 제거한다. 시험·읽기·파일럿 공동 배정의 학생 목록과 보호자 연결에서 대상 ID를 제외한다. 다른 학생의 수행과 배정은 유지한다. 제거 후 대상의 운영 표와 배정·관계에 자료가 남았는지 같은 트랜잭션에서 다시 확인한다.

새 개인자료 저장 표가 추가되었는데 삭제 기준 목록에 없으면 실행을 막는다. 표 목록 등록만으로 그 표의 실제 개인정보 처리가 검증되는 것은 아니며 구현과 검사 보완이 필요하다. 공동 자유 서술·기관 정책·다른 학생의 기록에 남은 이전 담당자 식별·내용은 자동 제거 대상으로 가장하지 않고 별도 보존·검토 대상으로 구분한다.

보호자에게 유효한 연결 자녀나 기존 처리정지의 종속 영향이 남으면 삭제를 거절한다. 실제 정당한 보호자 인계·확인·동의와 기존 정지 범위 검토를 먼저 진행해야 한다. 학습 기록을 보호자와 함께 삭제하지 않는다. 마지막 운영자는 다른 운영자에게 인계하기 전 삭제할 수 없다. 계정을 삭제한 운영자의 공동 수업과 다른 학생의 기록도 계정과 함께 삭제하지 않는다.

대리인이 제출했던 이번 삭제 요청의 최소 결과·본인 접수 이력은 대상의 일반 보호자 연결 제거 후에도 해당 접수자에게 안내할 수 있다. 다른 과거 학습·권리 사본에 대한 접근을 복원하지 않는다. 삭제된 계정의 추가 열람·정정 등 권리 행사는 학원의 별도 본인 확인 접수로 처리해야 한다. 계정 삭제나 요청 취소로 이미 실행한 조치를 되돌리지 않는다.

## 별도 암호화 보존과 만료

검토 사본은 `retained_personal_records`의 암호화한 메타데이터와 `retained_personal_bodies`의 별도 암호화 본문으로 나눈다. 목록은 큰 사본 본문을 읽고 복호화하지 않는다. 기존 독립 `READX_DATA_KEYS`와 AES-256-GCM, 임의 nonce·기관·보존 ID·본문 버전 AAD를 사용한다. 색인의 기관·대상·자료 종류·작업 ID·종료일·버전을 인증된 본문과 대조하고, 사본 본문은 별도 해시·건수·ID를 검증한다.

원장만 재인증 후 50건씩 별도 보존 목록을 조회한다. 일반 교사·보호자·다른 기관의 원장은 접근할 수 없다. 보존 목적 검토 참조를 기록한 다운로드도 현재 권한·재인증·반출 목적과 접속기록 저장이 필요하다. 다운로드는 학원 내부 보존 검토용 사본이며 정보주체에게 실제 전달·수령된 상태를 뜻하지 않는다.

종료일이 지난 사본은 다운로드하지 못한다. 새 실제 보존 근거가 있으면 종료일을 연장하며 이전 결정·종료일·담당자·시각을 암호화한 이력에 남긴다. 버전이 바뀌면 오래된 연장·파기 요청은 거절한다. 원장이 실제 만료·후속 조치를 확인하면 메타데이터와 본문 운영 행을 함께 제거한다. 기간이 남은 자료는 이 만료 파기 경로로 임의 제거하지 않는다. 이 과정도 장치·WAL·백업 파기 완료와는 구분한다.

한 삭제 검토의 대상 운영 자료는 현재 32MB 한도를 둔다. 그보다 큰 자료는 운영자의 별도 분할·검증 절차가 필요하며 이를 법적 삭제 권리 범위의 한도로 사용하면 안 된다.

## 원자성·매체·복원 경계

일반 이용 제한, 세션·복구·초안 키 회수, 자료 분리·제거, 삭제 결과·접속기록은 같은 SQLite 트랜잭션에서 처리한다. 감사 기록 저장이 실패하면 전체 작업을 취소한다. 기존 접속기록의 서명 연결을 끊어 삭제하거나 과거 로그를 몰래 다시 쓰지 않는다.

서버 연결에 SQLite `secure_delete=ON`을 적용했다. 이는 삭제·갱신 시 SQLite가 처리하는 내용을 덮어쓰는 조치이며 과거 WAL 프레임·외부 백업·SSD·파일시스템 사본·프로세스 메모리·사용자 반출 자료의 파기 검증을 대신하지 않는다. WAL checkpoint/정리, 중단·복구 통제와 별도 삭제 원장으로 백업 복원 뒤 재적용하는 도구는 후속 작업이다. 현재 결과에서 `mediaAndBackupsVerified`를 참으로 바꾸는 API는 제공하지 않는다.

[개인정보 보호법 제21조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsId=011357&lsJoLnkSeq=900078908&print=print)의 불필요해진 자료 파기와 별도 보존, [제36조를 포함한 현행 법령](https://www.law.go.kr/lsInfoP.do?lsiSeq=289415)의 삭제 요구·조사·통지와 다른 법령의 예외를 검토 기준으로 확인했다. 실제 적용 근거·자료별 보유기간과 통지는 운영 당사자·법률 검토가 필요하다. SQLite 동작은 [공식 PRAGMA 문서](https://www.sqlite.org/pragma.html)와 [WAL 문서](https://www.sqlite.org/wal.html)를 근거로 구현 범위와 한계를 구분했다.
