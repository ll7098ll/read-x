초5 1회차의 실제 창작 지문과 24문항을 학생 응시, 교사 운영, 학부모 리포트에 연결했다. 세 역할은 서버에 저장된 동일한 응시 기록을 조회한다. 기존 브라우저 연습과 체험 기록은 유지하며, 새 기능은 `#/exams`에서 시작한다.

## 실행

검증 환경은 Windows, Node.js 24.14, npm 11.9다. `node:sqlite`를 지원하는 Node 24 환경에서 실행한다.

```powershell
cd webapp
npm run build
npm run serve:exam
```

기본 주소는 `http://127.0.0.1:5186/#/exams`다. 처음에는 서버 컴퓨터에서 교사 계정과 반을 만든다. 기본 계정이나 공통 비밀번호는 없다.

1. 교사: 학생·보호자 메뉴에서 학생과 연결 보호자 계정을 등록한다.
2. 교사: 시험지·해설 검토 후 학생과 응시 기간을 선택해 배정한다.
3. 학생: 해당 계정으로 로그인하고 응시 안내를 확인한 뒤 시작한다.
4. 학생: 45분 안에 답안을 제출한다. 회차 마감이 더 이르면 안내된 시각에 종료된다.
5. 교사: 개인 결과와 문항별 선택 분포를 확인하고 회차를 종료하여 학생 결과를 공개한다. 응시 중인 학생이 있으면 공개할 수 없다.
6. 교사: 지도 의견을 작성하고 연결 보호자에게 결과를 공개한다. 공개한 의견은 별도 스냅샷으로 보존하며, 수정 의견은 다시 공개해야 반영된다.
7. 교사: 문항별 보충을 배정한다. 학생의 원문 복습 → 별도 글의 선택 답과 작성 근거 → 교사 근거 검토가 같은 리포트에 연결된다.

개발 모드는 `npm run dev -- --host 127.0.0.1 --port 5185`다. `READX_EXAM_PORT`, `READX_EXAM_HOST`, `READX_EXAM_DB`로 서버 주소와 저장 위치를 지정할 수 있다. 기본 서버는 이 컴퓨터에서만 접속된다.

## 콘텐츠와 화면

| 문항 | 지문 | 주된 확인 목표 |
| --- | --- | --- |
| 1–4 | 책이 제자리를 찾는 방법 | 여러 조건과 우선순위 적용 |
| 5–8 | 빗물을 천천히 보내는 화단 | 원인과 과정 연결 |
| 9–12 | 숫자 뒤에 남은 질문 | 표의 분모와 판단 가능한 범위 |
| 13–16 | 의자를 옮긴 자리 | 인물의 행동과 마음의 변화 |
| 17–20 | 운동화의 오후 | 표현의 효과와 화자의 마음 |
| 21–24 | 고쳐 쓰는 수리 교실 안내 | 안내의 정확성과 수정 |

독서 12, 문학 8, 언어·매체 4문항이며 모두 5지선다다. 문항마다 정답, 다섯 선지의 판단 이유, 본문 근거 위치, 설명, 세부목표가 있다. 목표별 후속 글 6개를 별도로 집필했다. 표의 조사 수치는 창작 자료로 표시했다.

학생은 지문·문항 화면, 답안 현황, 다시 보기 표시, 큰 글자, 저장 상태, 남은 시간, 제출 확인을 사용한다. 모바일은 지문과 문제를 전환한다. 새로고침하면 서버 답안과 기기 복구 큐, 지문 위치를 복원한다.

리포트에는 정답·오답·미응답, 환산점수, 영역·읽기 행동·목표별 결과, 전체 선지 해설, 근거 위치, 교사 의견, 후속 학습 기록이 있다. 교사는 문항별 실제 선택 인원과 해당 학생을 확인한다. 보호자는 연결 자녀의 공개 결과와 함께 나눌 질문을 본다. 리포트의 인쇄 버튼은 전체 24문항을 펼쳐 브라우저 인쇄/PDF 저장을 연다.

문항당 1점, 미응답 0점이며 환산점수는 `정답 수 / 24 * 100`을 소수 첫째 자리로 반올림한다. 전국 등급, 백분위, 규준 점수는 산출하지 않는다. 후속 활동은 원래 성적을 바꾸지 않는다. 재노출 글은 새 글 성공으로 중복 집계하지 않으며, 선택 답 정답과 교사의 작성 근거 검토를 구분한다.

## 저장과 권한

- 서버 원장은 `webapp/.exam-data/readx.sqlite`다. Git 및 정적 배포 대상에서 제외한다. 서버 종료 후 데이터 디렉터리를 복사해 백업할 수 있다.
- 비밀번호는 scrypt 해시, 세션은 HttpOnly 쿠키로 처리한다. 새 로그인은 이전 세션을 해제한다. HTTPS 운영 시 `READX_COOKIE_SECURE=1`이 필요하다.
- 서버가 응시 권한, 문항·선지 범위, 답안 순서, 마감, 제출 확정을 검사한다. 중복 시작·제출과 역순 답안 저장을 처리한다.
- 시작 시 시험지를 고정한다. 정답과 해설은 서버 콘텐츠에만 두고 학생용 초기 번들·응시 응답에서 제외한다.
- 교사, 본인 학생, 공개된 연결 자녀의 보호자만 기록에 접근한다. 학생 결과 공개와 보호자 공개를 분리하고 보호자 공개 회수를 지원한다.
- 서버는 주기적으로 마감 처리한다. 브라우저가 닫혔다가 돌아와도 서버의 최종 유효 답안으로 채점한다. 마감 뒤 미전송 답안은 자동 합산하지 않으며 기기에 남은 미확인 문항을 안내한다.
- 모든 시각은 UTC 밀리초로 저장하고 화면에서는 한국 시간으로 표시한다.

## 검증

`npm run build`는 TypeScript 검사, 화면·데이터 검사 73개, 서버 통합 검사 4개, Vite 패키징을 수행한다. 신규 검사는 콘텐츠 구조·해설 비노출, 실제 계정별 권한·공개, 두 학생의 서로 다른 점수와 선택 분포, 역순 저장·중복 제출·마감, 로그인 교체, 보호자 공개 회수, 후속 활동 및 교사 검토, SQLite 재시작 후 제출 답안 보존을 확인한다.

브라우저에서는 검증 계정으로 학생 등록·배정·24문항 응시·새로고침 복원·제출·교사 분석·학생 공개·보호자 공개·문항별 보충·새 글 확인·교사 근거 검토를 수행했다. 검증 학생의 23/24 정답은 세 역할에서 95.8점으로 일치했고 후속 수행 뒤에도 유지됐다. 검증 화면은 `output/mock-exam-g5/`에 보관한다.

화면 검증 데이터는 별도 `.exam-data/qa-2026-10-24.sqlite`에 저장했다. 기본 실행 데이터베이스와 분리되어 있으며 실제 학생 자료가 아니다.

390px 모바일 화면에서 지문·문제 전환, 답 선택과 서버 저장, 학부모 리포트를 확인했다. 전체 화면의 가로 넘침은 없었고, 두 번째 지문에서 새로고침 후 이어하기가 해당 지문과 저장 답안을 복원했다. 미응답 23개를 포함한 제출 안내와 공개 대기 화면도 확인했다. 실행 번들에서 신규 문항의 비공개 선지 해설이 포함되지 않음을 검사했으며, 정적 서버의 콘텐츠 원본과 DB 경로는 404로 차단된다.

## 리드엑스 통합과 공통 디자인

학생·교사·학부모 홈과 공통 헤더에서 모의고사로 진입하고 각 역할의 학습 화면으로 돌아간다. 역할별 주소는 `#/student/exams`, `#/teacher/exams`, `#/parent/exams`이며 기존 `#/exams`도 유지한다. 주소의 역할은 진입 안내용이고 실제 권한과 화면은 서버 로그인 계정에 따른다.

모의고사도 기존 `BrandHeader`, `PageHeading`, `Dialog`, 공통 푸터와 디자인 토큰을 사용한다. 로고·남색 헤더·파란색 강조·학생용 금색 버튼·카드·모바일 메뉴를 일원화했다. 시험 지문은 기존 읽기 화면의 본문 서체를 적용한다. 학생의 기존 12문항 개인 연습은 실제 24문항 모의고사와 구분해 유지한다.

각 역할 홈의 `ExamEntryCard`는 실제 로그인 계정의 배정·응시·제출·공개 리포트·후속 활동을 조회한다. 로그인 전에는 가상 성적이나 인원 수를 만들지 않는다. 학습 체험 기록과 서버 모의고사 기록의 저장 범위를 화면에 안내한다.

통합 후 77개 자동 검사와 최종 빌드가 통과했다. 브라우저에서 세 역할의 홈↔모의고사 이동, 실제 집계, 기존 23/24·95.8점 및 문항별 리포트 보존, 새 회차 배정·답안 저장·제출을 확인했다. 공통 제출 창의 Escape 닫기와 다시 열기, 390px 모바일 리포트의 가로 넘침 없음, 뒤로 가기 복원도 확인했다. 검증용 추가 응시는 별도 QA 데이터베이스에 저장했다.

화면 증거는 `output/mock-exam-g5/integrated-student-home.png`, `integrated-teacher-home.png`, `integrated-parent-home.png`, `integrated-exam-player.png`, `integrated-report.png`, `integrated-report-mobile.png`다.

## 이번 범위와 남은 운영 준비

초5 1회차의 로컬 서버 구현이다. 외부 배포와 다기관 운영 환경은 아직 구성하지 않았다. 학생·보호자가 각자의 기기에서 외부 접속하려면 지속 실행 서버, HTTPS, 저장소 백업, 계정 복구와 기관 관리가 추가로 필요하다. 현재 SQLite 원장은 소규모 시범용이며 대규모 운영 DB 설계가 아니다.

콘텐츠는 교사 검토용 창작 시범 문항이다. 교육과정 연결은 검토 후보이며 전문가 검수·난도 보정·실제 초5 사용성 시범을 거쳐야 한다. 정답 정정·문항 무효·재채점, 서버측 마감 후 복구 심사, 보호자 연결 변경, 다기관 관리, 초6 및 다른 회차 확장은 후속 단계다.

주요 코드는 `webapp/server/content/g5-01.mjs`, `webapp/server/exam-service.mjs`, `webapp/server/start.mjs`, `webapp/src/components/exam/ExamPortal.tsx`, `webapp/src/services/examApi.ts`, `webapp/src/types/exam.ts`, `webapp/src/exam.css`다.
